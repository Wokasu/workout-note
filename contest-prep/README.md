# Contest Prep 🏁

ボディビル・フィジーク競技者向けの、大会までの減量を管理する食事管理アプリ（PWA）。
体組成計（タニタ ヘルスプラネット）のデータを CSV で取り込んで、PFC の目標と減量ペースの判断に使います。

## 機能

- **PFC 目標の自動計算**
  - 基礎代謝：体脂肪率があれば除脂肪量から（Katch-McArdle）、なければ Mifflin-St Jeor
  - 大会日・目標体重から必要な週あたり減量を出し、上限（既定は体重の1%/週）を超えないように赤字を設定
  - たんぱく質は体重×g/kg、脂質はカロリーの%、炭水化物は残り
  - **今あるデータから維持カロリーを推定（反映は自分で選ぶ）**：直近4週間の「食事を記録した日の平均摂取」と「体重の傾き（最小二乗）」から維持カロリーを出す。食事3日分・4日以上あけた体重2回分から使え、±幅と信頼度（高 ±150以内／中 ±350以内／低）を表示。摂取が中央値の6割未満の日は記録漏れとみて除外。今日・分析タブ（と確認期間のカード）の「目標カロリーに反映する」で採用し、「計算式の値に戻す」でいつでも戻せる
  - **維持カロリーを記録から毎週更新**：計算式の値から始めて、毎週「直近14日の平均摂取 ＋ 体重（7日平均）の変化」から維持カロリーを計算し、推定値をその値へ30%ずつ近づける（1回の更新は最大±150kcal、食事の記録が6割未満の週は更新しない）。減量中・増量中どちらでも動き、確認期間が終わったらその実測値に合わせ直す。分析タブで推移を確認できる
  - コーチ指定の PFC をそのまま使うことも可能
- **大会までの計画（米海軍式の体脂肪率）**
  - 身長・首・ウエスト（女性はヒップも）から米海軍式（Hodgdon & Beckett）で体脂肪率を推定し、除脂肪体重と FFMI を出す
  - 体脂肪率は「自動（海軍式を優先）／海軍式／体組成計」から選べ、基礎代謝の計算にも使う
  - 目標体重は自分で入力する。その前に、除脂肪体重を保ったまま大会でよく目安にされる体脂肪率（男性 4〜10%、女性 10〜18%）になる体重と、それぞれに必要な週あたりのペースを一覧で出す（上限ペース内で一番絞れるものに「おすすめ」）。行を押すとその体重が入る
  - 週ごとの計画表：過去は計画と実績（7日平均）の差、これからは今の体重から上限ペース内で引き直した計画と、その時の体脂肪率の目安
- **増量期（オフ）の計画**：設定の「今の時期」で切り替え
  - 上限体重 ＝ 今の除脂肪体重から出したコンテスト体重（大会時の体脂肪率、標準 男性5%・女性12%）＋ 幅（標準 10kg）。筋肉が増えれば上限も上がる。推定コンテスト体重は体脂肪率 ±1%（男性なら4〜6%）の幅で表示
  - 維持カロリーに余剰を足す。余剰は +100kcal から始め、毎週、直近2週間の増え方を目標ペース（標準 月+1kg）と比べて ±50kcal ずつ調整する（3/4 未満なら増やす、1.5倍超なら減らす、その間は据え置き。上限 +500kcal）
  - 次の大会日が入っていれば、見込みどおり増量したときの体重から「月2〜3kg のペースで大会当日にコンテスト体重になるには、いつ減量（維持確認を含む）に入ればよいか」を逆算して表示。時期が来たら「コンテスト減量に切り替える」ボタンが出る
  - 体重（7日平均）が上限に達したらプチダイエット（週0.75%）に切り替え、上限 − 3kg まで落としたら最初の余剰から増量を再開。これをくり返して波をつける（数値はすべて設定で変更可）
  - **プチダイエットは手動でも始められる**：計画タブで「どこまで落とすか」を決めて今日から開始（維持確認の設定があればそこから）。その体重（7日平均）まで落としたら増量に戻る。途中で目標を変えたり、やめて増量に戻したりもできる（上限で自動に入ったものも）。自分でやめたあとは、上限を一度下回るまで自動では入らない
  - 計画タブに、大会まで（大会日がなければ26週）の摂取カロリーと体重の見込みと、増量・プチダイエット・大会減量の切り替え時期をグラフと一覧で表示
- **減量前の維持カロリー確認（キャリブレーション）**：コンテスト減量の開始日から、または増量期で上限に届いたとき（プチダイエットの前）に、標準14日間は推定の維持カロリーで食べる（0日で無効）
  - 期間中の平均摂取と体重（7日平均）の変化から実際の維持カロリーを測り、終わってから4週間はその値を基準に赤字を決める（記録が7割以上のとき）
  - コンテスト減量では確認期間のぶん減量に使える日数が減るので、必要ペースと計画線もそれに合わせる
- **文章で食事を記録**：「鶏胸肉一枚、ご飯大盛り」「なか卯、親子丼 大盛り」のように書いて判定
  - 登録済みの食品は別名（鶏胸肉・むね肉・ご飯…）と量の言葉（1枚=300g、1杯=150g、大盛り=1.5倍、半分、漢数字）からアプリ内で即判定。鶏むね肉は特に書かなければ皮なし
  - 判定できないもの（外食・市販品など）は claude.ai の公開ページから Claude に PFC を推定してもらう（`sample` 機能。初回に許可の確認あり）
  - 結果は追加前に量・PFC を直せる。推定したメニューはマイ食品に保存すると次から即判定
- **食事記録**（アプリを開くと最初に表示）：食品の候補は「炭水化物（ご飯・パン・麺・いも）」「タンパク質（肉・魚・プロテイン・卵・乳・大豆）」「脂質（オイル・ナッツ）」「その他」のタブで分類。マイ食品はPFCのうち一番カロリーの多い栄養素のタブに自動で入る（どれも半分未満なら「その他」）。1〜6食目に、食品と量（g・個など）を選ぶと PFC を自動換算。直接入力した食品はマイ食品として保存。最近の記録のワンタップ追加、前日の食事のコピー
- **iPhone のヘルスケアから取り込み**：「すべてのヘルスケアデータを書き出す」で作った export.zip を選ぶと、体重・体脂肪率・ウエストを読み込む（zip のまま端末内で展開しながら読むので、大きなファイルでも可。lb・inch は換算）
- **体組成計データの取り込み**
  - ヘルスプラネットの CSV（Shift_JIS / UTF-8）を列名から自動判定。外れたら列ごとに割り当てを修正できる
  - 「日付, タグ, 値」の縦長形式（ヘルスプラネット API のタグ 6021 体重・6022 体脂肪率 など）にも対応
  - ウエスト・胸囲・上腕などのサイズは手入力、または他のアプリ・スプレッドシートの CSV から取り込み
  - 同じ日に複数回測っている場合は一番早い時刻（朝）の値を使う
- **分析**：体重・体脂肪率・ウエストなどの推移グラフ（7日平均・開始→大会の計画線）、週ごとの平均体重・前週比・平均 kcal/PFC
- **バックアップ**：JSON で保存・復元

## データの保存先

- **claude.ai の公開ページで開いた場合**：ページの保存領域（db）に保存し、スマホと PC で同期します。所有者だけが読み書きできるルール（`read/write: owner`）で公開しているので、ページを共有しても記録は見えません。保存領域が空のときに開くと、そのブラウザにあった記録を自動で移します。
  - `prep/profile`・`prep/foods`、食事は月ごとの `logs/YYYY-MM`、身体データは年ごとの `body/YYYY` にまとめて保存
- **それ以外（開発サーバー・GitHub Pages など）**：ブラウザの localStorage にだけ保存します。
- どちらの場合もブラウザに控えを置き、開いた直後はそれを表示します。

## 開発

```bash
cd contest-prep
npm install
npm run dev           # 開発サーバー
npm test              # ユニットテスト（vitest）
npm run build         # 型チェック + 本番ビルド（dist/）
npm run build:single  # 1ファイルにまとめた dist/contest-prep.html を作る
```

`dist/` は相対パスでビルドされるので、GitHub Pages などの静的ホスティングに置いてスマホのホーム画面に追加できます。

> 数値は推定値です。家庭用体組成計の体脂肪率は水分の影響を受けやすいので傾向として見てください。極端な減量や水抜きは体調を崩すことがあります。
